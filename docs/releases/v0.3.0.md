# ServerUI v0.3.0

Stage 2 añade servicios systemd cargados, captura de journal y acciones rápidas
con confirmación explícita. Dashboard y procesos conservan solo lectura.
Linux usa los permisos existentes del usuario; no hay sudo, agente de
autenticación ni cambios automáticos de polkit. Windows conserva demo aislada.

- Servicios: filtro por unidad, selección, logs acotados y acciones iniciar,
  detener, reiniciar y habilitar al arranque. Habilitar no inicia.
- Confirmación vinculada a unidad/operación; cancelación sin acción e historial
  volátil de 16 resultados. Una operación en vuelo, worker diferido separado.
- Comandos con argumentos separados, sin shell, y límites de 5 s/256 KiB.
  Un timeout no garantiza cancelar ni revertir el job enviado a systemd; no hay
  reintentos automáticos de mutaciones.
- TUI con barras CPU/RAM/swap, tabla de montajes y selección invertida. Conserva
  40×12, ASCII, ausencia de color y renderizado por cambios, sin animaciones.
- Procesos Linux optimizados con una lectura acotada de proc/stat por PID,
  baselines por inicio/ticks y sin retener descriptores ni leer argumentos,
  entorno o tareas. sysinfo mantiene métricas generales y discos.

Después de extraer el paquete Linux x86_64:

```sh
./serverui --ascii --no-color
./serverui --demo
```

Windows x86_64: `./serverui.exe --demo`. En Servicios: `/` filtra, Enter abre
logs, a/d/R/e proponen acciones, y confirma y n/Escape cancela; h abre historial.
q o Ctrl+C sale (q es texto al editar filtro). Se requiere terminal interactiva.

Validación local: fmt, Clippy, 49 tests Rust Windows/57 Linux, regresión del
empaquetador, siete pruebas de seguridad del fixture, PTY/SSH y smoke físico en
Ubuntu Server 22.04.5. En la laptop, el benchmark real de 60 s a refresco 1000 ms
pasó de 3,98 % a 0,90 % de un núcleo y de 4,15 a 3,66 MB máximos de RSS. Son
muestras locales cortas, no garantías universales ni percentiles.

El usuario sustituyó la VM por una prueba física controlada por SSH. Ocho casos
de acciones reales pasaron en el gestor systemd del usuario, con denegación de
escritura, fallo, timeout responsivo, estados independientes y fixtures retirados.
Esto no valida polkit del gestor del sistema, boot del host o rollback mediante
snapshot. Los logs del sistema se comprobaron aparte en lectura.

Se adjuntan binarios GNU Ubuntu 22.04/glibc ≤2.35 y Windows MSVC, construidos por
CI desde main, checksums individuales y SHA256SUMS con LF. Comprobar SHA-256 antes
de instalar; ver docs/INSTALL_UBUNTU.md y CHANGELOG.md.

Límites: solo unidades cargadas y nombres ASCII admitidos, máximo 2048 servicios,
80 líneas de journal, permisos que pueden ocultar datos y diagnósticos acotados.
Las acciones pueden cortar servicios y SSH. No hay señales a procesos, APT,
administración de red/discos ni persistencia de configuración/historial. La
licencia open source sigue pendiente; no se introduce una por inferencia.
